# 持仓按钮迁移到持仓概览卡片设计

## 背景

当前基金详情页中，“录入持仓 / 编辑持仓”按钮位于顶部工具栏，与目标基金选择、刷新操作并列。  
用户希望将该入口移动到“持仓概览”卡片中，使操作语义与持仓数据聚合在同一区域，减少视线来回切换。

## 目标

1. 将“录入持仓 / 编辑持仓”入口从顶部工具栏移动到“持仓概览”卡片头部右上角。
2. 保留现有持仓录入弹窗、配置保存、详情刷新和按钮状态切换逻辑。
3. 顶部工具栏移除重复入口，避免同一动作出现两个位置。
4. 保持详情页现有卡片风格、间距和信息层级，不做无关重构。

## 非目标

1. 不修改持仓弹窗字段、校验规则或保存流程。
2. 不调整“收益区间”“均线与位置”卡片内容。
3. 不新增持仓相关的第二入口、快捷入口或悬浮按钮。

## 设计决策

### 方案选择

采用“**卡片标题栏右上角图标+文字按钮**”方案。

原因：

1. 动作入口与持仓指标聚合，语义最直接。
2. 比把按钮混入指标网格更清晰，不会把动作误读为数据。
3. 比卡片底部单独一行更紧凑，符合桌面端详情卡片头部操作习惯。

### 结构调整

当前 `detail_section_card(title, subtitle, tiles)` 只支持静态标题区。  
将其轻量扩展为支持可选头部动作控件，例如：

- 左侧：标题 + 副标题
- 右侧：可选 action 控件
- 下方：指标卡网格

只有“持仓概览”卡片传入该 action；其他卡片继续不传，保持现状。

### 按钮表现

按钮放在“持仓概览”卡片标题栏右上角，采用“**图标 + 文字**”形式：

1. 无持仓时显示“录入持仓”。
2. 已有持仓时显示“编辑持仓”。
3. 图标与颜色语义继续沿用现有 `_detail_holding_action_config()`。

### 控件形态调整

当前顶部入口 `btn_detail_holding_action` 是 `ft.IconButton`，不能直接满足“图标 + 文字”展示。  
本次将其替换为卡片头部使用的**文本按钮类控件**（例如 `ft.Button`），按钮内容同时展示图标和文案。

对应地，现有配置与刷新逻辑也需要扩展：

1. `_detail_holding_action_config()` 除 `icon / tooltip / bgcolor` 外，还要返回 `label`。
2. `_refresh_detail_holding_action()` 需要同步更新按钮的图标、文案、tooltip 和样式。
3. 按钮点击处理仍复用 `open_current_target_holding_dialog()`，不改交互入口方法。

顶部工具栏中的 `btn_detail_holding_action` 不再参与布局展示。

## 状态与数据流

### 复用现有状态逻辑

继续复用：

1. `_detail_holding_action_config()`：决定图标、文案、背景色。
2. `_refresh_detail_holding_action()`：在基金切换、详情刷新、持仓保存后同步按钮状态。
3. `open_current_target_holding_dialog()`：按钮点击后继续打开同一录入弹窗。

### 刷新行为

以下时机仍需同步卡片内按钮状态：

1. 当前基金切换后；
2. 详情面板刷新后；
3. 保存持仓成功后；
4. 本地缓存与详情数据重新应用后。

本次只改变按钮宿主位置，不改变触发链路。

### 刷新契约

卡片内按钮必须在以下场景中保持“图标 / 文案 / tooltip”同步一致：

1. 当前基金没有持仓时，显示“录入持仓”。
2. 当前基金已有持仓时，显示“编辑持仓”。
3. 在详情页内切换到另一只基金后，按钮立即切到该基金对应状态。
4. 保存持仓成功并刷新详情后，按钮从“录入持仓”切换到“编辑持仓”。
5. 重新应用缓存详情数据时，按钮状态不回退成旧值。

## UI 细节

1. 卡片头部保持当前模块卡片的字体、颜色和间距风格。
2. 按钮应与卡片标题顶部对齐，不挤压副标题文本。
3. 窄宽度下允许标题区与按钮自然换行，但按钮仍应留在卡片头部范围内。
4. 按钮文本应直接可见，不再依赖仅 tooltip 才能理解功能。

### 响应式验收

至少验证以下结果：

1. 按钮始终位于“持仓概览”卡片头部区域内，不掉到指标网格中。
2. 标题“持仓概览”和副标题说明仍完整可读，不因按钮出现而被明显截断或重叠。
3. 当宽度不足时，标题区与按钮允许换到两行，但仍保持“头部信息在上、指标卡在下”的层级。

## 测试与验证

新增或更新回归测试应覆盖：

1. 顶部工具栏不再包含持仓按钮。
2. “持仓概览”卡片头部包含持仓动作按钮。
3. 无持仓时按钮配置为“录入持仓”。
4. 有持仓时按钮配置为“编辑持仓”。
5. 切换基金后按钮文案、图标与 tooltip 会同步刷新。
6. 保存持仓成功后按钮状态会从“录入持仓”切到“编辑持仓”。
7. 应用缓存详情数据后按钮状态不会回退。
8. 现有持仓弹窗入口点击方法不变。

人工验证关注：

1. 基金详情页中，按钮是否确实移动到“持仓概览”卡片右上角。
2. 顶部工具栏是否只保留目标基金选择和刷新按钮。
3. 点击卡片内按钮后，录入/编辑持仓弹窗能正常打开。

## 风险与控制

### 风险

1. 如果直接删除旧按钮而未同步新宿主，可能导致 `_refresh_detail_holding_action()` 找不到控件。
2. 若卡片头部布局处理不当，可能压缩标题/副标题，影响详情页信息层级。

### 控制

1. 保留按钮实例和刷新逻辑，仅调整其布局挂载位置与展示形式。
2. 优先做最小结构扩展，不为单一卡片引入新的复杂抽象。
3. 用回归测试锁定卡片位置与按钮配置。
